Worker_3 owns selection and duplicate-photo policy; this check is a last safety gate. ALASKA `camera_group` is the raw index name, and `camera_model` is normalized in the selection.

## Decode and grid rules

- ALASKA TIFF: one uncompressed RGB8 frame, three samples, unsigned values, contiguous planes, orientation 1, no extra samples. Reject alpha, palette, compression, other orientation, wrong shape, and wrong type. Return the stored pixels; do not apply ICC, rotate, resize, or pad.
- LSDIR PNG: one RGB8 image, no palette, alpha, or transparency; return stored pixels without color or orientation conversion.
- New records explicitly state `grid_policy=trim512`: start positions `0,512,1024,...` within the photo. Discard the incomplete right/bottom edges. Only 512 tiles are supported. The old RAISE/DIV2K records continue to state `overlap_last`; their seeds and records do not change. New `photo_index` ranges start at 100,000 (ALASKA) and 300,000 (LSDIR), and seed codes for `trim512`, `test_seen`, and `test_unseen` are appended without renumbering old codes.

## Opt-in mix and evaluation

For notebook 05, select source weights with `V3_SOURCE_MIX=raise:0.4,lsdir:0.2,alaska:0.4`. This selects the source names; do not include DIV2K. Use `V3_TILES_PER_EPOCH=45000` for about 18,000 RAISE, 9,000 LSDIR, and 18,000 ALASKA tiles per epoch. `V3_SOURCE=decode` reads masters. The sampler selects tile identities without replacement within a source when enough tiles exist and draws a keyed new sample for each epoch. It groups chosen tiles by photo to avoid repeated full-photo reads. If a source has too few distinct selected tiles, it repeats them and prints `repeated_tiles` for each source at epoch start. Use `V3_TRAIN_PHOTO_FRACTION=1` for the full candidate pool. Keep `V3_SOURCE_MIX` unset to keep the exact default training schedule and its original RAISE/DIV2K coverage. `V3_NEW_DATA_ROOT` may point to a scratch root with `data/alaska/` and `data/lsdir/` manifests; masters stay below `/work/Datasets/`.

**Checkpoint selection decision:** With `V3_SOURCE_MIX` set, notebook 05 defaults to `V3_CHECKPOINT_VAL=capped`; with the mix unset, it still defaults to `standard`, with no change to its old train stream or validation. Capped validation is a fixed, seeded **simple pair sample** of at most `V3_VAL_CAP_RAISE=5000` RAISE val pairs; **all** ALASKA val pairs; and a fixed seeded sample of at most `V3_VAL_CAP_LSDIR=1500` LSDIR val pairs. DIV2K is excluded from the capped set but stays in the old standard validation and test. The two independent fixed seeds (2401 and 2402) do not use the run seed or epoch. Simple pair sampling preserves the old RAISE photo/tile weighting *in expectation*; round-robin camera stratification would overrepresent rare cameras. Samples are sorted back into source-record order. If a source has fewer pairs than its cap, keep all of them. Caps must be positive. QUICK keeps its normal 16-pair final validation subset for a short smoke run; the saved hash covers this actual subset, not the larger pre-QUICK cap.

`data_run_settings.json` records the cap targets, actual per-source pair counts, and SHA-256 of `validation_pairs.csv` (the exact ordered `cover_id,source` pair list). Resume refuses a changed pair list in the same output folder. The `val_pe` and `val_loss` used for checkpoint selection are for the capped **combined** set; `val_pe_raise`, `val_pe_alaska`, `val_pe_lsdir`, and corresponding `val_loss_*` are logged each epoch alongside them in CSV and TensorBoard (also `pe/<source>` and `loss/<source>` in the dedicated validation TensorBoard writer). Per-source numbers are diagnostic only, not extra checkpoint criteria. `V3_CHECKPOINT_VAL=standard` can still force original RAISE/DIV2K validation; `combined` retains all original and new val pairs if explicitly requested. This choice changes the model-selection target: do not compare resulting best-checkpoint P_E values as if they used identical validation sets. The standard test always filters to the original RAISE/DIV2K records. `V3_EXTRA_TESTS=source-panels` evaluates the best checkpoint independently on ALASKA val, ALASKA test_seen, ALASKA test_unseen, LSDIR val, and LSDIR test. `V3_EXTRA_TESTS=test-bpp1,source-panels` also preserves the existing bpp-1 pass. Separate `extra-<source>-<split>/` directories hold predictions, setting hashes, and metrics; the default remains `test-bpp1`. The standalone `scripts/eval_checkpoint.py` accepts `--source alaska|lsdir --split val|test_seen|test_unseen|test --manifest-root <root>` (valid source/split combinations only). Neither extra panel selects a checkpoint.

**Expected full validation size:** `min(5000,RAISE val pairs) + ALASKA val pairs + min(1500,LSDIR val pairs)`; with about **1,500 ALASKA** pairs and sufficient LSDIR photos, about **8,000 pairs**, versus the old 11,238 validation pairs and unchanged 10,956 standard-test pairs. The *temporary smoke selection* added 11 new validation pairs to the uncapped set and has 3 ALASKA seen-test, 8 ALASKA unseen-test, and 7 LSDIR test pairs. These are not final selection sizes. Recompute the actual count and hash from final selections; do not mistake the QUICK 16-pair subset for the full cap.

**G4 per-epoch estimate, not a measurement:** earlier XuNet R2 validation ran 703 16-pair batches in about 12–13 s; the older wide G4 run measured 13.163 s from its first to last validation batch for the same 11,238 pairs. Simple count scaling to 8,000 gives **~8.5–9.3 s** of old-model validation span; allow **~9–15 s XuNet and ~9–17 s wide** for altered TIFF/PNG input and model mix, plus first-batch/worker startup (formerly ~19 s with nonpersistent workers, but now persistent by default; PC first-wait fell from 4.78 to 0.87 s). Thus a cautious total is **~10–35 s/epoch XuNet and ~10–37 s/epoch wide**, excluding the first epoch's setup/compile. This is a planning range, not a post-fix G4 benchmark; final source inventories, decode cost, and retained-worker waits are still unknown.
