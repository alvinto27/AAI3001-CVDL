# Plan: supervise XuNet's 32 px cells without changing the old stream

**Status (2026-10-21):** ~~not approved; on hold at the user's request.~~ The user made cell-level training the active work. This plan is out of date (512 tiles, XuNetWide, retired evaluation); a refreshed plan for the current stack is in progress and will replace it. **Design only.** No model, generator, notebook, or G4 job changes are authorized by this plan. The [mixed-source result](../results/result-newdata-1.md) and [PC check B](../results/result-check-b.md) are the baselines: the mixed model's ALASKA unseen-camera FA at a validation-picked 5%-FA cutoff is **5.93%**, but overall miss is **24.20%** and k1 miss **66.16%**. At that same cutoff, unseen k1 miss rises from **40.0%** in the lowest clean-tile KV-noise quartile to **87.7%** in the highest. High clean scores and weak-stego misses often occur on noisy/textured tiles. The existing cell pictures are diagnostic by-products, not a trained localization output.

## 1. What the generator actually supplies

- `lsb_engine.embed()` already returns a **selected-pixel mask** for the slow/public API. It marks selected RGB-unit positions collapsed to pixels, including units whose value did **not** change. The fast OTF path instead uses `embed_fast()`, which returns stego pixels and metadata but **no selected-position mask by default**. `embed_fast(..., return_changed_units=True)` optionally returns sorted changed *RGB-unit indices*. Mode 2 already uses this option for its full-photo change counts; Mode 1 (`lsb_mode1.make_sample`) and the paired `lsb_torch` training loader do **not** request or pass spatial labels today. They have only `units_used`, `units_changed`, bit mode, k, method, placement, payload size and effective BPP in embedding metadata. A caller can compare the paired clean/stego tile bytes to recover changed pixels, but not selected-but-unchanged positions.
- Current placement choices are **`random`, `contiguous`, and `stride`**, on flattened interleaved RGB units. `random` samples across the *whole* 512 px tile. `contiguous` and `stride` may leave untouched spatial areas, but their extent depends on payload, start and stride; neither is an explicit 2-D rectangular region placement. The current train config draws lowest/plane k1–4, replace/match, strides 2/16, and BPP .05–.5. `write_masks: true` in that YAML does **not** make the OTF training loader return a cell mask.
- Proposed **opt-in** Mode 1 return: one `(16,16)` cell-label/count array per paired 512 px tile, plus the existing clean/stego tensors. On the stego generation call, get changed RGB-unit indices from the **same** embedding pass and reduce distinct pixel indices `unit//3` to cell `(y//32, x//32)`; count a pixel once if several channels changed. Clean covers get an all-zero array. Keep the dense record local to training, not in JSON metadata or frozen manifests. **Training augmentation matters:** `image_tensor` seeds horizontal/vertical flips and a 90° rotation with the embedding key **and image label**. The paired clean/stego images can get different transforms. Apply the *stego* (`label=1`) transform to its 16×16 target and ignored-cell map, with exactly the same keyed decisions and no extra RNG draws; the clean target remains all zero under any transform. Test alignment after each flip/rotation. If selected-position occupancy is studied later, expose the already computed sorted `selected` indices through an **opt-in** engine result; do not draw a new placement sample or infer positions from an unrelated RNG replay.
- With the feature **off**, call the unchanged two-result `make_sample`/three-result `embed_fast` paths, keep RNG calls, pair order, pixel arrays, train/validation/test settings hashes, metadata, default loader batch shape, and old notebook outputs byte-identical. Do **not** rewrite RAISE/DIV2K manifests or evaluation streams. An explicit new run name and setting must be required for region placement and the dense head. Test the off path against frozen digests before any G4 request. Region-mode seeds must be derived from a separate versioned stream; no extra random draws may enter the old path.

## 2. Cell target: observable changes versus selected positions

A 32×32 cell has **1,024 pixels**. Three possible labels answer different questions:

| Target | Good property | Problem |
| --- | --- | --- |
| `any changed pixel` | Clear, observable binary location, based on the actual stego tile; no selected-but-unchanged false target | One change can be below the model's resolving power; hard edges conflict with the ~48 px receptive field |
| `changed distinct-pixel share` | Continuous signal strength; unchanged bits do not masquerade as evidence | A real k1/.05-BPP cell may be only a few percent changed; literal BCE targets near zero can train it as nearly clean |
| `selected distinct-pixel share` | Knows where embedding **attempted** work; allows a signal even if a bit happened to match | Roughly half of random k1 selected units leave their value unchanged; a cell can have selected positions and **no** observable difference, so these are not reliable detection labels |

**Recommendation: hard occupancy (`changed distinct-pixel count ≥1`) with a reliability weight**, not a soft fractional target, for the first experiment. Use `w_pos = min(1, changed_distinct_pixels/16)` for a positive cell and `w_neg=1` for a truly unchanged cell; this gives sparse k1 cells a target without treating a single changed pixel as equally certain as a dense region. Keep an ablation of literal changed-pixel share and selected-position share *on training/validation only*; never choose the label definition by test P_E. A random k1 embedding at tile BPP .05 selects about 51 RGB units per cell on average and changes about half; almost **every** cell then has at least one change, so the hard label alone cannot teach clean cells inside such a stego tile. At smaller payloads or the edge of a localized payload, there may be just a few changes; report positive-count bins and check that the reliability weight does not erase weak k1 learning.

For the auxiliary cell loss, **ignore the one-cell boundary between known changed and unchanged regions** as an ambiguous supervision zone: the model sees neighboring pixels beyond the nominal 32 px cell. Count only unambiguous interior cells for the principal cell metric, and report boundary cells separately. Do not relabel every near-boundary clean cell as stego or hide boundary misses in tile metrics. Clean cover tiles are all-zero with no ignored cells.

## 3. Make mixed clean/stego cells on purpose

Keep the previous RAISE/LSDIR/ALASKA **40/20/40 source mix**, 45,000 tiles/epoch, existing paired clean+stego sampling, and evaluation settings for a controlled first comparison. **Within stego members of training pairs**, propose **50% localized region-random**, **25% original whole-tile random**, and **25% original contiguous/stride** draws. Every clean member remains a clean cover with all 256 cell labels zero. The whole-tile random quarter protects the old payload distribution and prevents a detector that works only on synthetic rectangles. A contiguous/stride sample counts as partial **only if its measured changed-cell map actually contains clean interior cells**; do not assume this from its placement name.

Add one explicit `region_random` placement confined to a seeded, cell-aligned rectangle, initially **128×128 or 256×256 px** (16 or 64 of the 256 cells). Sample RGB units uniformly without replacement *inside* that rectangle; place the rectangle across the tile, including corners and high-/low-noise content. Keep the same embedding methods and k values. At high global BPP a small region may not have capacity and local change density can become unrealistic. Prefer a separately recorded **local BPP** draw, cap it at a predeclared value (suggest .5 bit per region pixel), derive/report the actual whole-tile BPP, and stratify validation by *effective* BPP. Retain enough whole-tile stego training to cover the original .05–.5 tile-BPP range. A small read-only capacity probe and PC QUICK histogram must decide whether 128 px regions need a larger minimum or a different share **before** the G4 run; never silently clip most region samples. Record rectangle bounds, actual bits and changed-cell counts for the opt-in training stream, but do not put them in standard test records. The region changes the training distribution intentionally; source/payload comparability is checked by effective-BPP bins rather than assumed.

## 4. Loss and tile score

Use the existing tile cross-entropy (CE) on balanced clean/stego image pairs as the main objective. Add a **separate 1×1 auxiliary binary cell head** on the existing `(B, channels, 16, 16)` wide-model feature map. Train its logits with weighted per-cell binary cross-entropy (BCE), averaged within each tile and then across the batch so 256 negative cells cannot dominate one sparse positive. The proposed starting objective is `L = L_tile_CE + 0.2 × L_cell_BCE`. Start negative weight 1; cap the positive-class factor at **4** and apply the sparse-positive reliability factor above. Define the exact normalization in tests so an all-clean batch or a single sparse positive cannot cause a division-by-zero or an unbounded step. Log CE, BCE, fraction of positive/ignored cells, and gradient sizes separately; keep the weights fixed for the first run unless a *validation-only* check shows collapse. These constants are proposals to approve, not measured optima.

**Keep the old tile score for the first run:** `softmax(mean of the existing classifier's cell logits)`. The old tile head remains trained by tile CE; the new head supervises shared features without changing how checkpoint validation and the standard tests score a tile. The auxiliary cell head's probabilities are a **different map**. Do not silently replace the tile score by mean cell *probabilities* (not equal to softmax of mean logits), max, top-k, or noisy-OR. Max/top-k could detect a small localized payload but can amplify a single noisy clean cell into a tile false alarm; noisy-OR adds the same multiple-cell risk. Consider a **separate, preregistered ablation** of mean versus top-k only after the dense head has passed the first test with unchanged tile scoring.

## 5. Head geometry and map meaning

Notebook 05's `XuNetWide` freezes a KV 5×5 filter, then uses conv1/conv2 5×5, five 2×2 pools, and 1×1 later convs. A 512 px tile reaches a **16×16** grid of 32 px-spaced features. Tracing kernels and strides gives an approximate **48×48 px receptive field per feature cell**, larger than its nominal 32×32 label area; neighboring receptive fields overlap, including across a region boundary. Padding adds edge effects. Test the receptive field with an impulse/gradient probe before finalizing the ignored boundary rule.

`map_demo.py` currently computes the **existing tile classifier weights as a 1×1 convolution over that grid** (`cell_logits`), then displays per-cell softmax margins. Spatially averaging those logits before the classifier is the current tile inference. These maps were **never trained with local ground truth**. The proposed auxiliary 1×1 head starts new weights on the same grid; label its plots `auxiliary trained cell probability`, retain the old classifier-derived map for direct comparison, and prevent old checkpoints from being misread as trained dense heads. A new model checkpoint must carry an explicit head/version setting. Do not resume an old checkpoint *as if* it already contained the new head; a controlled warm start can load only matching trunk/tile weights and record the missing new-head keys.

Risks: labels near region boundaries contradict the 48 px receptive field; changed-pixel supervision penalizes imperceptible k1 cells; selected-position labels can claim a signal where none changed; positive cells can be swamped by clean cells or overpower tile CE; sharp synthetic rectangles can teach a region-artifact shortcut; region caps change the effective-BPP mix; max/top-k inflates clean false alarms; a new head or batch tuple can break old resume and test streams; cell metrics on synthetic local payloads may not transfer to whole-tile ALASKA/LSDIR tests. Measure each risk on validation before spending G4 time; keep tests held out.

## 8. Open user decisions (recommendations in bold)

1. **First objective:** **yes to a separate auxiliary cell head and unchanged mean-logit tile score**, rather than replacing the tile classifier or testing top-k in the first run. This isolates whether local supervision helps at the existing test interface.
2. **Target:** **hard `any changed distinct pixel`, reliability-weighted, with an ignored one-cell region boundary**. Do not label selected-but-unchanged bits as a detectable stego cell. Compare a fractional soft label only as a later, validation-planned ablation.
3. **Payload mix:** **50% cell-aligned region-random / 25% whole random / 25% old contiguous/stride among stego pairs**, retaining 40/20/40 source weights. Approve region sizes and local-BPP cap only after the PC capacity/histogram probe; keep clean pairs unchanged.
4. **Loss:** **tile CE + 0.2×auxiliary cell BCE, positive factor ≤4** with per-tile normalization, logged gradient scales and no test-guided retuning. Approve or alter this weight before training.
5. **Decision rule:** **require both stable validation-picked ALASKA unseen FA and a material k1-miss gain in the noisiest quartile**, without a standard-test regression beyond the frozen mark. If only the cell AUC improves, do not call the tile detector better.
6. **Resource gate:** **no G4 submit until feature-off parity, PC QUICK, full validation and a time estimate pass**, followed by explicit Orchestrator authorization. No code implementation follows automatically from approval of this document.
